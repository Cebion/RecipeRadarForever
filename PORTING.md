# Porting notes: Recipe Radar 1.x (WoW 1.12) to WoW Forever

Target: WoW Forever 1.60.x (`## Interface: 16001`), which runs the Midnight 12.1.5
Mainline addon API. The TOC also lists `120105` so the addon loads on Midnight.

Renamed in 2.2 to avoid clashing with the unrelated CurseForge addon "RecipeRadar"
(rakstar91, also on Forever): folder and TOC `RecipeRadarForever`, title "Recipe Radar
Forever", SavedVariables `RecipeRadarForever_SkillDB`, `_NameCache`, `_ItemCache`
(account) and `RecipeRadarForever_Options`, `_Filters` (character), global prefix
`RRF_` (functions, data tables, frames, the `RRF_S` localization lookup), key binding
`RECIPERADARFOREVER_TOGGLE`. Saved data from earlier versions is not carried over
(log in once per character to rebuild it). The slash command is `/rrf`. The window layout and art are unchanged.

## Data (2.1)

`RegionData.lua` and `RecipeData.lua` are generated by `tools/build_data.py`:

| Source | Used for |
|---|---|
| Original vanilla database (`tools/data/classic_*.lua`, Jay Miller) | gold prices, vendor notes (Seasonal, Roving...), specialties, reputation of the classic recipes |
| QuestieDB Forever (GPLv3), installed copy | which NPC sells which recipe item, NPC faction, spawn coordinates (Forever's own maps) |
| AllTheThings Forever data, installed copy | required skill, Merchant's Favor and token costs, reputation (FactionID), 13 vendor items QuestieDB lacks (certifications, token patterns, Darkmoon Faire schematic, 3 newer Favor plans) |
| `tools/data/overrides.json` | excluded items (two Season of Discovery leftovers in QuestieDB), continents of new zones |

Result (QuestieDB 1.0.11, AllTheThings 5.4.11): 768 vendor recipes, 290 vendors,
49 regions. 462 recipes are new in Forever, 320 cost Merchant's Favor (including the
6 certifications), 19 cost token items. Merchant's Favor counts per profession match
ForeverChanges exactly (Blacksmithing has 3 more, newer than that site's list).

- 131 recipes have no required skill in the data. It is read from the item tooltip
  at runtime ("Requires X (N)") and cached in `RecipeRadarForever_ItemCache`.
- 123 recipes have no price in the data (mostly new gold-vendor recipes; the gold
  prices on ForeverChanges are not reliable). Opening the vendor's merchant window
  records the real price or currency, also cached in `RecipeRadarForever_ItemCache`.
- 24 classic vendor/recipe pairs that QuestieDB doesn't list for that recipe (for example the
  Vendor-Tron 1000 and Super-Seller 680 robots) are placed at the NPC's Forever spawn.
- Region keys are English zone names, each with the client `UiMapID`. Region
  names in the UI come from `C_Map.GetMapInfo`, so they are localized everywhere.
- The in-window zone map is drawn from the client's map tiles
  (`C_Map.GetMapArtLayers`/`GetMapArtLayerTextures`); `Images/Regions` was removed.
- **Live import**: with QuestieDB installed, `Import.lua` reads its vendor data in
  batches after login and adds anything the snapshot lacks (in memory only).
  `/rrf questie off` disables it.
- NameMap.lua (craft window name to item name map) was removed. Known recipes
  are matched by item name from the tooltip scan.

## What changed in the code

| Area | 1.x | Forever |
|---|---|---|
| Lua | Lua 5.0 (`this`, `arg1`, `for k,v in t`, `table.getn`, `table.foreach`, `getglobal`, `mod`) | Lua 5.1, handler parameters, `ipairs`/`pairs`, `#`, `_G[...]`, `%`. `local addonName, ns = ...` in every file |
| Load | `VARIABLES_LOADED` | `ADDON_LOADED` (own addon) + `PLAYER_LOGIN` |
| Skill ranks | `CHAT_MSG_SKILL` parsing, opening CharacterFrame and scraping `GetSkillLineInfo` | `C_SkillInfo.GetNumSkillLines/GetSkillLineInfo` on `SKILL_LINES_CHANGED` |
| Known recipes | Craft/trade window scan (`GetTradeSkillInfo`, `GetCraftInfo`), `CHAT_MSG_SYSTEM` parsing, hidden GameTooltip scan | `C_TooltipInfo.GetItemByID` "Already known" check, on `NEW_RECIPE_LEARNED`, `LEARNED_SPELL_IN_SKILL_LINE`, `TRADE_SKILL_SHOW`, login and window open (throttled) |
| Specializations | Opening the spellbook and calling `CastSpell` on every profession (protected) | `C_SpellBook.IsSpellKnown(spellID)` with a table of specialization spell IDs (`ns.SpecialtySpells` in Globals.lua) |
| Reputation | Opening ReputationFrame and scraping `GetFactionInfo` | `C_Reputation.GetNumFactions/GetFactionDataByIndex` on `UPDATE_FACTION` |
| Item info | `GetItemInfo`, "Uncached Recipe" disconnect warning | `C_Item.GetItemInfo`, `Item:ContinueOnItemLoad` loads missing items and redraws, `C_Item.GetItemIconByID` for the icon |
| Zone lookup | `GetMapZones`, `GetMapContinents`, `RegionNameToID` | Region index built from `C_Map.GetMapChildrenInfo` under the player's world map, matched by zone name |
| Minimap pins | 20 hand-placed buttons, MapNotes scale tables, indoor zoom CVar hack, `GetPlayerMapPosition` polling every 0.1 s | TomTom waypoints if TomTom is loaded, otherwise the Blizzard user waypoint (`C_Map.SetUserWaypoint` + supertrack) |
| World map pins | 20 buttons on `WorldMapDetailFrame`, `WORLD_MAP_UPDATE`, replaced `WorldMapFrame` OnHide | TomTom, or a `MapCanvasDataProviderMixin` provider with a pin template (`RecipeRadarWorldMapPinTemplate`). Pins also show on continent and neighbouring maps via world coordinates |
| Dropdowns | `UIDropDownMenu*` | `WowStyle1DropdownTemplate` + `SetupMenu` (checkbox/radio menus) |
| Context menus | `UIDropDownMenu` "MENU" frames | `MenuUtil.CreateContextMenu` |
| Options | XML frame with `<Backdrop>`, `OptionsCheckButtonTemplate`, `OptionsSliderTemplate` | Lua frame with `BackdropTemplate`, `UICheckButtonTemplate`, `UISliderTemplateWithLabels`, plus a Settings > AddOns page with buttons that open it |
| Availability tooltip | `GameTooltipTemplate` + `SetBackdropColor` | `TooltipBackdropTemplate` frame, 24 lines (the old code allowed 24 but defined only 16) |
| List buttons | `NormalText`/`HighlightText` XML elements (removed from the schema), `SetHighlightTextColor` | `ButtonText` + `NormalFont`; the hover tint is applied in Lua so shared font objects are never changed |
| Sounds | `PlaySound("igMainMenuOption...")` | `PlaySound(SOUNDKIT.*)` |
| Chat link | `ChatFrameEditBox:Insert` | `ChatFrameUtil.InsertLink` with `IsModifiedClick("CHATLINK")` |
| Window | `ShowUIPanel`/`HideUIPanel` | plain `Show`/`Hide`, still closes with Escape (`UISpecialFrames`) |
| Minimap button | shape checks for third-party minimap addons, permanent `OnUpdate` | Round placement only. `OnUpdate` exists only while the button flashes. Right-click opens the options |
| Saved data | String compare of `Options.Version` | numeric `RecipeRadarForever_Options.dbVersion` for future migrations (unknown professions and regions are dropped on load) |

New: search box, delete stored character data (options), "Report a problem" window
(`/rrf report`, vendor menus; GitHub issue templates in `.github/`), drag the minimap
button, `/rrf options`, `/rrf debug maps`, `/rrf debug scan`, `/rrf debug where`,
AddOn compartment entry, `## IconTexture`.

## Removed and why

- **Spellbook, CharacterFrame and ReputationFrame scraping, `CastSpell` on professions**:
  protected or taint-prone and no longer needed; replaced by the APIs above.
- **Chat message parsing** (`CHAT_MSG_SKILL`, `CHAT_MSG_SYSTEM`): replaced by
  events. Chat payloads can also be secret inside instances on Forever.
- **MapNotes-style minimap math and the world map button overlay**: the 1.12 map
  API is gone. TomTom or the Blizzard waypoint replaces it.
- **Third-party hooks** (EnhTooltip, RecipeBook, minimap shape addons):
  those addons don't exist on Forever.
- **`/rrf debug vendor`**: replaced by `/rrf debug where`.
- **Professions, regions and vendors that are not in the vanilla game** were
  dropped from the data. Old saved data for them is removed by the migration.

## Globals

Besides SavedVariables, `SLASH_RECIPERADARFOREVER1`, `SlashCmdList.RECIPERADARFOREVER`
and the two `BINDING_*` strings, every global uses the `RRF_` / `RRF` prefix: the
functions referenced from XML handlers and across files, the generated data tables,
the named frames, and `RRF_S` (localization). `RRFWorldMapPinMixin` is global because
the XML pin template names it.

## Combat and secret values

The addon reads no combat, unit, aura or chat data. Nothing touches secure frames.
Map waypoints and window show/hide are not protected.

## Needs in-game verification

1. `/dump select(4, GetBuildInfo())`: confirm 16001.
2. `/rrf debug maps`: every vendor zone resolves to a game map (uiMapIDs come
   from QuestieDB's Forever zone table; continents are 1414/1415).
3. In-window map: the zone art draws from the client tiles and the scroll icons sit
   on the vendors. Stand on a few vendors and compare with `/rrf debug where`.
   Check Mount Hyjal, Riverglades and Zephras Isle, and one of the 26 classic-only
   vendor entries (for example Vendor-Tron 1000 in Desolace).
3a. `/rrf verify`: number of recipe items unknown to the server (should be 0) and
   recipes still without a required skill after the tooltip scan.
3b. Merchant's Favor: the Redridge/Barrens camp vendors show "30 Merchant's Favor"
   etc. Open one merchant window: prices of its recipes update (gold, Favor or token).
3c. `/rrf questie`: import status and how many recipes/vendors QuestieDB added.
4. Specialization spell IDs in `ns.SpecialtySpells` (Globals.lua) with
   `/dump C_SpellBook.IsSpellKnown(9788)` etc. on a specialized character.
5. Skill names returned by `C_SkillInfo.GetSkillLineInfo(i).name` match the
   profession names (`/rrf debug skills`).
6. Reputation standings for Argent Dawn, Cenarion Circle, Thorium Brotherhood,
   Timbermaw Hold and Zandalar Tribe appear in `/rrf debug skills`.
7. "Already known" detection: learn a vendor recipe, and within a second it moves
   from "Available Now" to "Already Known".
8. TomTom (if used): `TomTom:AddWaypoint(mapID, x, y, opts)` works on Forever and
   pins show on the minimap and world map. Without TomTom: world map pin plus the Blizzard waypoint.
9. Dropdowns: the checkbox menus keep open while you click, filters apply, and
   the recipes tab radio list switches profession.
10. Seasonal vendors hide or show with the option.
12. Search: typing filters both tabs (recipe, vendor, zone); clearing restores the
   list; mapped vendors keep their pins while searching. Check that the search box does
   not overlap the radio icon or the dropdowns.
13. Options > Stored character data: delete an alt, confirm, it disappears from the
   availability tooltips. The options window's new rows don't overlap.
14. `/rrf report` and right-click a vendor > Report data problem: link and details
   appear and can be copied with Ctrl+C.
11. A fresh install creates the RecipeRadarForever_* saved variables without errors, and alts appear after one login each.
